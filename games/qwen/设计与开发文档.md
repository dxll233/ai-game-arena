### 1.1 创意说明

经典 2048 的"2 的幂次合成"天然对应修仙体系中的"境界递进"：
每一次合成都是一次"突破"，数字越大境界越高，最终合成 2048 即"飞升成仙"。
第二轮在保留经典模式的基础上，加入"试炼秘境"（6 个固定挑战盘）与"法术"
（消耗灵气的有代价操作），把单局无尽模式扩展为"无尽 + 关卡 + 资源抉择"三层玩法。

## 2. 核心玩法设计

### 2.1 基本规则（经典修仙模式，与 v1 一致）

1. 4×4 棋盘（"洞天福地"），初始随机生成 2 个境界牌。
2. 玩家通过 方向键 / WASD / 触屏滑动 控制所有境界牌向一个方向移动。
3. 两个相同境界的牌相撞时合成为更高一层境界（数值翻倍），每次移动中每个牌最多参与一次合成。
4. 每次有效移动后，在随机空格生成 1 个新牌（90% 概率为"练气"=2，10% 概率为"筑基"=4）。
5. 合成获得的境界值累加进"修为"（分数）。
6. 无效移动（该方向无任何位移与合成）不生成新牌、不消耗步数、不改变结算状态。

### 2.2 胜负与结算（v2 集中整理的结算优先级）

每次有效移动、生成新牌并完成动画后，按以下优先级结算（`settleAfterMove`）：

1. **挑战达成**：挑战模式下本步合成出的最大值 ≥ 该盘目标 → "试炼达成"结算，写入该盘通关纪录。
2. **首次飞升**：经典模式合成出 2048 且未弹过飞升 → "飞升成仙"结算；
   - "继续修行"：解除结算继续游戏（`keepPlaying=true`）；**若继续时盘面已无合法步，立即转入失败结算**，不得锁死；
   - "再入轮回"：重开经典局。
3. **死局失败**：棋盘无合法步 → "道消身陨"结算（可"时光倒流"撤销或重开）。
4. **步数耗尽**：挑战模式限步用完且未达成 → "劫数已尽"结算（可撤销或再战）。

安全网：无效移动发生时（`onInvalidMove`），若盘面已无合法步且未处于结算中，
同样进入失败结算——保证任何路径都不会把玩家永久锁在无法结算的状态。

### 2.3 境界数值表（核心配置）

| 数值 | 境界 | 数值 | 境界 |
| --- | --- | --- | --- |
| 2 | 练气 | 128 | 合体 |
| 4 | 筑基 | 256 | 大乘 |
| 8 | 金丹 | 512 | 渡劫 |
| 16 | 元婴 | 1024 | 真仙 |
| 32 | 化神 | 2048 | 金仙（飞升） |
| 64 | 炼虚 | 4096+ | 道祖（超越飞升） |

### 2.4 试炼秘境（6 个固定挑战盘，v2 新增）

每盘固定初盘 + 固定随机种子（或禁用落子），保证可复现；可反复重试；通关纪录逐盘独立保存。

| 编号 | 名称 | 目标 | 限步 | 种子 | 落子 | 初始棋盘 |
| --- | --- | --- | --- | --- | --- | --- |
| c1 | 试炼一·聚气成丹 | 64 | 不限 | 11 | 有 | `2 2 4 0 / 4 8 0 0 / 2 4 8 0 / 0 0 0 0` |
| c2 | 试炼二·金丹速炼 | 256 | 100 | 22 | 有 | `8 8 16 0 / 16 32 64 0 / 8 16 32 0 / 0 0 0 0` |
| c3 | 试炼三·一气化三清 | 256 | 30 | 0（禁落子） | 无 | `128 64 32 16 / 8 4 2 2 / 0 0 0 0 / 0 0 0 0` |
| c4 | 试炼四·十面埋伏 | 512 | 90 | 44 | 有 | `64 32 16 8 / 8 16 32 64 / 128 64 0 0 / 0 0 0 0` |
| c5 | 试炼五·渡劫生死局 | 1024 | 80 | 55 | 有 | `256 128 64 32 / 64 128 256 16 / 16 32 64 8 / 0 0 0 0` |
| c6 | 试炼六·飞升之路 | 2048 | 160 | 66 | 有 | `512 512 256 128 / 256 128 64 32 / 0 0 0 0 / 0 0 0 0` |

设计校验：限步盘的"初盘总值 + 限步×期望落子值(2.2)"必须 ≥ 目标值 + 终局残牌余量，
否则数学上不可解（v2 开发中据此修正过 c2/c4/c6 的限步与 c4/c5/c6 的初盘）。
c3 为纯残局谜题：初盘总值恰为 256，必须零浪费级联合成（存在 9 步手工解，见测试）。

### 2.5 法术系统（v2 新增，有代价、有边界）

每局固定 3 点灵气（界面以灵珠显示）；施法进入同一撤销历史；施法失败（资源不足/调息中/牌数<2）
不产生任何状态变化、不入撤销历史。

| 法术 | 灵气 | 调息（冷却，按有效移动计） | 效果 |
| --- | --- | --- | --- |
| 乾坤挪移 | 1 | 2 步 | 用种子随机源 Fisher-Yates 重排全部牌位（牌面集合不变）；重排后若成死局同样进入失败结算 |
| 焚天化劫 | 2 | 3 步 | 用种子随机源在最小值牌中随机移除一张 |

限制设计：灵气总量 3 点（最多 1 次化劫 + 1 次挪移，或 3 次挪移），调息期内同法术不可连发，
保证法术是"有代价的应急手段"，不能无成本绕过 2048 规则。

### 2.6 辅助系统

- **修为 / 巅峰修为**：当前分数与经典模式历史最高分（localStorage 持久化，键 `wd2048_best`，沿用 v1 键天然兼容迁移）。
- **试炼纪录**：独立键 `wd2048_challenges_v1`，结构 `{ 盘id: { cleared, bestMoves } }`；挑战得分不覆盖经典巅峰。
- **时光倒流**：撤销上一步（快照栈，最多回退 20 步；第 21 次撤销不响应）。
- **重启轮回 / 再战此关**：按当前模式重开。
- **突破提示**：首次合成出更高境界时，屏幕中央浮现"突破！xx境"飘字。

### 2.7 撤销快照（v2 完整化）

每次有效移动/成功施法前压栈，快照包含会影响后续行为的**全部**局内状态：
`values、score、mode、wonShown、keepPlaying、highest、lingqi、cdShift、cdDissolve、movesLeft、movesUsed、rngState`。
恢复时逻辑层整体回滚，DOM 表现层由棋盘整盘重建（不序列化 DOM/动画锁）。
巅峰修为是跨局数据，不随撤销或切换模式回退。

## 3. 界面与交互设计

### 3.1 布局（竖屏优先，桌面自适应）

```
┌──────────────────────────────┐
│  问道2048·修仙录              │
│  [修为 1234] [巅峰 5678]      │
│  [经典修仙] [试炼秘境]   ← 模式标签 │
│  [灵珠●●●][乾坤挪移·1灵][焚天化劫·2灵] │
│  [时光倒流] [重启轮回]         │
│  （挑战模式额外显示：试炼信息条 名称/目标/余步） │
│  ┌──┬──┬──┬──┐               │
│  │  │  │  │  │  4×4 棋盘      │
│  └──┴──┴──┴──┘               │
│  操作提示：方向键/WASD/滑动    │
└──────────────────────────────┘
```

"试炼秘境"标签打开选关面板：6 张挑战卡片（名称、规则说明、通关徽章"已通关·最佳N步/未通关"、入定挑战按钮）。
结算遮罩四种：飞升成仙（win）、试炼达成（challenge-clear）、劫数已尽（nomoves）、道消身陨（lose）。

### 3.2 视觉风格

- 国风深色底（墨青 → 玄黑渐变），鎏金标题；favicon 为内联 SVG（自制，无外部资源）。
- 境界牌按境界递进换色：低境界青灰布衣 → 中境界紫金 → 高境界鎏金流光。
- 动画：新牌"凝聚"缩放浮现、合成牌"突破"弹跳、移动平滑过渡（130ms，与 CSS transition 对应）。
- 结算/飞升使用全屏半透明遮罩 + 卡片。

### 3.3 输入

| 平台 | 操作 |
| --- | --- |
| 桌面 | ↑↓←→ 方向键、WASD |
| 移动端 | 棋盘区域上下左右滑动（阈值 24px，防止误触） |
| 通用 | 按钮点击（撤销 / 重开 / 法术 / 模式 / 结算按钮） |

动画期间（130ms）锁定输入，避免状态竞态；连按与长按重复触发均被动画锁吸收。
回合制玩法无实时倒计时，窗口失焦/切回不影响局内状态（实测验证）。

## 4. 技术方案

### 4.1 模块划分（单文件内逻辑分层）

| 模块 | 职责 |
| --- | --- |
| CONFIG | 境界表、法术表、挑战盘表、尺寸、概率等常量 |
| State | 棋盘状态（4×4 Tile 对象）、分数、模式、灵气/调息、胜负标志、撤销快照栈、officialRun |
| Logic（纯逻辑层） | `applyMove`（同步、无动画依赖）、`settleAfterMove`、`canMove`、`spawnTile`、`applySpell`、快照捕获/恢复 |
| Render | DOM 创建与定位（绝对定位 + transform）、动画类、面板刷新 |
| Input | 键盘监听、触摸滑动手势识别 |
| Storage | localStorage 读写（按模式隔离的两个键） |
| Audio | WebAudio 极简音效（合成/突破/胜负），失败自动降级为静音 |
| Debug | `window.__wd2048` 测试钩子：写操作置 `officialRun=false`，阻止写纪录/存档；`getState` 只读不置假 |

### 4.2 关键数据结构

```
Tile { id, value, row, col, el, mergedThisTurn }   // 每个牌是持久 DOM 元素，便于移动动画
grid[4][4] -> Tile | null                           // 逻辑棋盘
snapshot { values, score, mode, wonShown, keepPlaying, highest,
           lingqi, cdShift, cdDissolve, movesLeft, movesUsed, rngState }
Random { state, seed(s), next() }                   // mulberry32，可注入种子
```

### 4.3 移动/合成算法（2048 标准算法）

1. 依据方向确定遍历顺序（向左移动则从左到右遍历，其余方向类推）。
2. 对每个牌：沿方向找到最远可到达空位；若下一格是等值且本回合未合成过的牌，则合成。
3. 合成产生的新牌数值翻倍，双方来源牌动画滑到目标格后移除，新牌以"突破"动画出现。
4. 任一牌位置或合成发生变化 → 本步有效 → 生成新牌（挑战禁落子盘除外）、更新修为/巅峰、进入结算优先级判定。
5. `applyMove` 在移动循环**开始前**捕获快照（循环会原地修改棋盘），无效移动直接返回 null 且不压栈。

### 4.4 随机源与确定性

- mulberry32 可注入种子；挑战盘开局用固定种子（禁落子盘种子无意义），同盘同输入序列结果完全一致（测试重复 20 次验证）。
- 经典正式局用时间戳播种（不可复播，符合"每局不同"预期）；测试中可覆写种子。
- 撤销恢复 `rngState`，保证"撤销后重做"的落子与之前一致。

### 4.5 自适应布局

- 应用容器宽度 = `min(94vw, 440px)`；JS 依据容器实际像素计算格子坐标，
  监听 `resize` 重新定位所有牌。实测桌面 893×764、1280×720 与移动 390×844 均无溢出。

### 4.6 兼容性与降级

- 不使用任何外部资源（字体/图片/库/网络请求），离线可玩。
- 音效使用惰性创建的 AudioContext，异常时静默降级。
- localStorage 读写全部 try/catch 包裹，不可用时降级为仅内存记录。
- 触屏监听 touchstart/touchend，`touch-action: manipulation` 防止双击缩放干扰。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 动画与状态竞态导致牌错位 | 动画期锁输入；动画结束后统一重建 DOM 快照 |
| 胜利+死局同现导致锁死（v1 缺陷） | 结算优先级集中处理 + 继续按钮内检查 + 无效移动安全网，三层保障 |
| 快照不完整导致撤销后行为漂移（v1 缺陷） | 快照含胜利状态/灵气/调息/随机源等全部局内状态，回归测试逐项断言 |
| 挑战盘数学上不可解 | 设计期按"初盘总值+限步×2.2 ≥ 目标+残牌余量"校验；六盘均有参考解（c3 为手工解） |
| 移动端滑动手势误触 | 位移阈值 24px；取主轴方向 |
| 调试捷径污染成绩/存档 | `officialRun` 标志：调试钩子的写操作置假，禁止写纪录与通关证据 |
