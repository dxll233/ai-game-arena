## 4. 手动检查清单对应（题目第 4/5 条）

- **失焦/切回**：blur 自动暂停 + 暂停中帧冻结（diffFrac，见 §3）；切回不自动续跑，Esc 恢复，恢复后计时继续推进、无卡键。
- **按键释放/连按**：R/空格 14 连按不重开、不暂停（mash-test stayed:true）；终局后单按 R 重开实时实测 ×5。胜利后终局连按 R×10 的动作因实时未通关未触发（实时层面未验证，R1 单测覆盖连重 10 次状态干净）。
- **升级弹窗**：选牌期间游戏冻结；多级连升依次发牌（单测 B1-9 + 实战 levelup 日志）。
- **重复结算**：Boss 死亡只一次胜利（B3-5 单测：同帧多弹/重复调用 killEnemy 幂等）；失败/胜利后终局演出 1.5/1.8s 内输入不触发跳转。
- **连续重开 10 次**：单测 R1（vm 沙箱连重 10 次逐字段断言）+ 实时失败后 R 重开 ×5（freshOk）；实时胜利后的终局连按未执行，如实记为未验证。
- **视口**：1280×720（截图 01-07）与 893×764（截图 08-10）均等比缩放、无变形/溢出；893 宽为上下信箱留边。**未承诺触屏：不测 390×844、未在实体手机验证。**
- **控制台错误/资源缺失**：CDP 监听 `Runtime.exceptionThrown` 与 console error/warning + `window.onerror/unhandledrejection`：整局 0 异常（见 §3 summary）；无网络请求（单文件、无外链资源，DevTools Network 无条目——代码内无任何 URL 字面量）。
- **内容溢出**：升级卡最长描述（过载贯穿/标记追猎 2 行）在卡内完整显示；结算面板数据卡不重叠（截图 05/06）。

## 6. 未覆盖范围与如实披露

1. **实时链路胜利（未验证）**：两轮共 8 次自动化闯关均未通关（死亡时间 01:38–02:11，最好战绩为第一跑第 3 局 02:00 进入 Boss 阶段 I、02:11 战死，kills99/LV9）。Boss 双阶段机制由 B3-1~B3-5 单测与场景采集截图 04/05 覆盖，阶段 I 有实时实拍；但"实时打通/二阶段实战/胜利后终局 R×10"均不作为已验证项。第三跑（§3.6）仅作补充，不改变上述定性。失败原因是自动驾驶规避/输出强度不足，非观察到的游戏缺陷；评审手动试玩可复验完整流程（Cap 场景脚本 `tests/capture/cap.html` 可确定性复现二阶段与胜利画面）。
2. 触屏/移动端：未做虚拟摇杆，未测 390×844，非实体手机。
3. Firefox/Safari/Edge：本轮仅 Chrome 实测；代码只用标准 API（Canvas2D/WebAudio/Set），无 Chrome 专有特性，但不替未测浏览器下结论。
