# 回响 / ECHO（第三轮）

> 你无法同时出现在两个地方 —— 但过去的你可以。

一款浏览器网格解谜游戏。你的每一步都被记录，每隔几拍，一个「过去的你」会从几拍前的位置诞生，把你刚走过的路重演一遍，然后**定格在那一刻你所站的位置**。用这些残像去压住踏板、骗过守卫、替你站在你分身乏术的地方。

**第三轮新增**：**时间望远镜（V）**——花一拍预演残像将定格的位置、下一只残像的出生点、原地不动的死亡预警；15 关（新增千里眼 / 双星定位 / 观测者）；存档 schema 2（校验和 + 旧档迁移 + 坏档回退）+ 静音设置持久化。

**11-06 关卡重设计**：根据玩家反馈修复了「8–14 关不用解密、直接走过去就行」——第 2、8–15 关的门全部改为**几何割集**（关掉门就到不了出口），参考解重新机器求解；新增 `tools/audit.js` 逐关证明「禁用全部回响后无法通关」，并写进 `verify.js` 永久断言。

**11-07 终章守卫回归**：按玩家反馈把第 15 关的门后守卫加回，放在门后的走廊里（不破坏割集），让「门开了还得挑对拍」成为终章最后一重时序约束。反事实验证：咽喉前多等一拍，有守卫被抓、无守卫仍能通关；单点扰动容错从 7/53 收窄到 1/53。详见 `ROUND2_CHANGELOG.md` 与 `TEST_REPORT_ROUND2.md`。

## 启动（可直接玩）

**双击 `index.html`**，用 Chrome、Edge 或 Firefox 打开。

- `file://` 协议直接可用，**不需要**服务器、Node、构建、联网、账号或安装任何东西
- 也可任意静态服务器托管；游戏无任何外部请求
- 桌面 / 移动端均可（移动端有屏幕虚拟方向键）

完整启动步骤：打开文件 → 标题界面点「开始游戏」→ 方向键 / WASD 移动 → 走到发光出口即通关。卡住按 `H` 看参考解演示（**演示不写入纪录**），按 `P` 暂停，按 `Z` 撤销，按 `V` 预演，按 `R` 重来。

## 操作

| 键 | 作用 |
| --- | --- |
| `↑ ↓ ← →` / `W A S D` | 移动一拍（时间只在行动时前进） |
| `空格` / `.` | 原地等待一拍（凑触发时机） |
| `V` | **时间望远镜**：预演一拍（= 等待 + 显示确定性预测，有节拍代价） |
| `Z` / `Backspace` | 撤销上一拍（完整本局无限） |
| `R` | 重来本关 |
| `P` | 暂停 / 继续（窗口失焦会自动暂停） |
| `Esc` | 关卡列表 |
| `H` | 参考解自动演示（不写入正式纪录） |

## 规则速览

- 每 **T 拍**诞生一个残像：从 T 拍前的位置出现，重走最近 T 拍，最后**定格**。触发那一刻你站在哪，它最终就停在哪。**第 1 关 T=6，其余关卡 T=4**，HUD 常驻倒计时。
- 残像上限 **M** 个，超出时最老的消失（FIFO）。
- 压力板 `a b c d` **全部**被压住时，对应门 `A B C D` 才开 —— 玩家和残像都算「压住」。门在拍初求值并冻结整拍。
- 守卫沿直线巡逻；踏进残像所在格时残像碎裂，守卫被迷惑、停顿一拍并掉头。
- 时间水晶 `o` 是出口钥匙，但拾取会**净化全部残像** —— 顺序很重要。
- **时间锚 `^`**：踩上后记录「位置 + 拍数」；之后诞生的本拍新回响**起点**改到记录点（动作序列不变，落点整体平移）。再次踩锚覆盖；记录点不可通行或被占据时回响保留原起点。撤销可完整回滚。
- **尖刺压力板 `!`**：既是 a 通道压力板又是尖刺。你踩上去必死，回响却能站 —— 所以只有被锚点投送或恰好路过的回响能压住它。
- **时间望远镜 `V`**：预演 = 等待一拍。青色准星 = 残像将定格的位置；红 ✕ = 它会中途被守卫撞碎；紫菱形 = 下一只残像出生点；红脉冲 = 原地不动会死。预测在你下一步行动后过期。
- 每关最多三星：通关 / 集齐星尘 / 步数 ≤ par。**15 条内置参考解全部集齐星尘与水晶**。
- 参考解演示、暂停、撤销、重来都**不会污染**正式星级 / 最佳步数 / 解锁。

## 15 关梯度

初醒 → 定格 → 双生 → 猎犬 → 荆棘 → 净化 → 回声之厅 → **投送 → 覆盖 → 净化 → 险径 → 回声之厅·终章** → **千里眼 → 双星定位 → 观测者（终章）**。
第 1、3–7 关原样保留；第 2、8–15 关在 11-06 重设计为「门是唯一通孔」的布局，每关一个新教学点，且**每关的机制都是解题必要条件**；第 15 关于 11-07 再加回门后走廊守卫（开门只是开始，还要挑准通过拍）。完整机制表与各关 T/M/par 见 `docs/设计文档.md` §4。

## 开发与验收

需要 Node ≥ 22（仅验收脚本用），游戏本身不需要。

```bash
node tools/audit.js             # 15 关机关必要性审计（门割集 + 禁用回响不可通关）
node tools/verify.js            # 15 关参考解 + 撤销回放 + 锚点必要性 + 机关必要性
node tools/regress.js           # 62 项回归
node tools/smoke.js             # 无头 15 关按键回放 + 演示隔离
node tools/guard_evidence.js    # 第 15 关守卫反事实量化（有守卫 vs 无守卫）
node tools/redesign15.js        # 第 15 关守卫候选重验
node tools/solver.js 8          # 重新求解某一关
node tools/probe.js 8 --map     # 逐步查看某关状态
node tools/browser_playtest.js  # 真实浏览器试玩（需本机 Chrome），产出截图与结果 JSON
node tools/release_check.js <目录>  # 验证任意目录的玩家版可启动可通关
```

改动关卡地图后务必先跑 `redesign.js` 验证候选，再跑 `audit.js` 与 `verify.js`（两者都会断言门割集与机关必要性）；改动渲染坐标后务必重跑 `browser_playtest.js`（A0 逐格断言）。

验收结论、A0—A8 每条的状态与证据、真实试玩进度、性能实测与未覆盖范围，全部记录在 `TEST_REPORT_ROUND2.md`；剩余问题见《已知问题.md》。
