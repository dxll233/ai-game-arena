# 《回响 / ECHO》开发文档（第三轮最终版）

本文档描述第二轮交付后的最终实现。与第一轮的逐项差异、原因与兼容处理见 §8。
验收编号与证据见 `TEST_REPORT_ROUND2.md`。

## 1. 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | 原生 JavaScript（ES2017，无框架、无构建） | 零依赖，双击即玩 |
| 渲染 | Canvas 2D | 网格游戏足够；插值动画自行实现 |
| 模块方式 | 传统 `<script>` 按序加载 + IIFE 挂全局 | `file://` 下 ES Module 会被 CORS 拦截；UMD 写法使同一份引擎既跑在浏览器、又能被 Node `require` |
| 音频 | Web Audio API 实时合成 | 无音频资源文件 |
| 存档 | `localStorage`（键 `echo.progress`） | 保存通关进度、星级、最佳步数 |
| 校验 | Node CLI 脚本复用同一份引擎源码 | 保证「校验过的关卡 = 玩家玩到的关卡」 |
| 真实浏览器试玩 | Chrome DevTools Protocol，Node 22 内置 `fetch` + `WebSocket` | 零 npm 依赖，可驱动真实 Chromium 按键、截图、读 DOM/Canvas 自检 |

**运行要求**：任意现代浏览器即可游玩（双击 `index.html`，`file://` 可用），不需要 Node、服务器或联网。
**开发/验收要求**：Node ≥ 22（用了全局 `WebSocket`/`fetch`）+ 本机 Chrome/Edge（仅 `tools/browser_playtest.js` 需要）。

## 4. 数据结构

### 4.1 静态地图（字符表）

| 字符 | 含义 | 字符 | 含义 |
| --- | --- | --- | --- |
| `#` | 墙 | `A B C D` | 门（对应通道 a/b/c/d） |
| `.` | 地板 | `*` | 星尘 |
| `S` | 起点 | `x` | 尖刺 |
| `E` | 出口 | `o` | 时间水晶 |
| `a b c d` | 压力板 | `^` | **时间锚**（第二轮新增） |
| `!` | **a 通道尖刺压力板**（第二轮新增：玩家致命、回响可站） | `↑ ↓ ← →` | 守卫及初始朝向 |

解析产生静态层 `tiles[y][x]`，每格 `{ wall, plate, door, exit, start, star, spike, crystal, anchor, ch }`，以及 `start/exit/plates/doors/guardStart`。
`!` 同时置 `spike=true` 与 `plate='a'`，并把坐标加入 `plates.a`。

### 4.2 运行时状态（可深拷贝以支持撤销）

```js
state = {
  def, levelId, name, cols, rows, T, M, par, hint,
  step: 0,
  timeline: [],                     // timeline[i] = 第 i+1 拍的动作
  history: [{x,y}],                  // history[i] = 第 i 拍末玩家位置
  player: {x, y},
  echoes: [{ id, x, y, seq, i, bornStep, done, fromAnchor }],
  guards: [{ x, y, dir }],
  stars: [{ x, y, taken }],
  crystals: [{ x, y, taken }],
  anchor: null | { x, y, step },    // 第二轮：时间锚记录
  status: 'playing' | 'won' | 'dead',
  deathCause: null | 'spike' | 'guard',
  events: []
}
```

`clone()` 跳过 `def`（保留引用），其余逐字段 `JSON` 深拷贝 —— 因此 `anchor` 与回响起点都能完整回滚。

## 5. 核心算法

### 5.1 索引约定（全部实现基于此）

- `timeline[i]` 是第 `i+1` 拍的动作，执行后玩家从 `history[i]` 到达 `history[i+1]`。
- 执行完 `step` 拍后：`timeline.length === step`，`history.length === step + 1`。
- 回响从 `history[step-T]` 出发，依次执行 `timeline[step-T .. step-1]`（共 T 个），无阻挡时必定到达 `history[step]`。

### 5.2 单拍推进伪代码（`applyAction`）

```
if status != 'playing': return

timeline.push(action); step++
ev = []
open = evaluateDoors(state)              # ① 拍初快照，本拍门状态冻结

# ② 回响先动（按诞生顺序）
for e of echoes where !e.done:
    a = e.seq[e.i]; e.i++
    move(e, a, open)                     # 墙/关门阻挡 -> 原地不动
    if e.i >= e.seq.length: e.done = true; ev.push(ECHO_FROZE)

# ③ 玩家移动
target = player + dir(action)
if !blocked(target, open): player = target
if tile(player).spike: status='dead'; cause='spike'; return
if crystal at player: 收集; 清空 echoes; ev.push(ECHO_PURGED)
if star at player: 收集
if tile(player).anchor:                 # ③' 时间锚：覆盖记录
    anchor = { x, y, step }
    ev.push(ANCHOR_SET)
if 玩家与守卫同格: status='dead'; cause='guard'; return

# ④ 守卫移动
for g of guards:
    next = g + dir(g.dir)
    if blocked(next) or 其他守卫在 next: g.dir = 反向; continue
    if 有残像在 next: 碎裂全部该格残像; g.dir = 反向; ev.push(GUARD_STUNNED); continue
    g = next
    if g == player: status='dead'; cause='guard'; return

# ⑤ 记录玩家本拍末位置
history.push(player)

# ⑥ 回响诞生（每 T 拍，且 step > 0）
if step % T == 0:
    born = { id:'e'+step, x:history[step-T].x, y:history[step-T].y,
             seq: timeline.slice(step-T, step), i:0, bornStep:step,
             done:false, fromAnchor:false }
    echoes.push(born); ev.push(ECHO_BORN)

    # ⑥' 时间锚生效：只作用于本拍新建、创建序号最小的回响
    if anchor && anchor.step < step:
        legal    = !blocked(state, anchor.x, anchor.y, open)   # 非墙、非关闭的门
        occupied = 玩家在锚点 || 守卫在锚点 || 其它回响在锚点
        if legal && !occupied:
            born.x = anchor.x; born.y = anchor.y; born.fromAnchor = true
            ev.push(ANCHOR_APPLIED)
        else:
            ev.push(ANCHOR_IGNORED)     # 保留原起点，绝不随机改选

    while echoes.length > M: 淘汰最老; ev.push(ECHO_EXPIRED)

# ⑦ 胜负：抵达出口且集齐本关全部时间水晶
if tile(player).exit && crystals.every(taken): status='won'; ev.push(WIN)
else if tile(player).exit: ev.push(EXIT_LOCKED)
```

注意 ⑥ 在拍末，回响下一拍才开始走第一步，视觉上「落后」玩家 T 拍。
`anchor.step < step` 保证「记录之后」才生效；「本拍没有新回响」天然不进入 ⑥'，不触发。

### 5.3 压力板与门求值

```
for channel of ['a','b','c','d']:
    plates = 该通道全部压力板坐标（含 ! 格）
    pressed = plates.every(p => 玩家在 p || 任意回响在 p)
    doorOpen[upper(channel)] = pressed      # 无该通道板时恒关
```

### 5.4 坐标变换（A0：第二轮最高优先级）

**第一轮缺陷**：`render.js` 只有 `px(gx) = ox + gx*cell + cell/2`，实体把纵坐标也用它，而墙/板/出口用 `oy + y*cell`，纵向漂移 `ox-oy`（在 893×420 非正方形画布上实测 153px）。

**修复**：唯一入口

```js
screenX(gx) = ox + gx*cell + cell/2
screenY(gy) = oy + gy*cell + cell/2
gridToScreen(x, y) = { x: screenX(x), y: screenY(y) }
cellBox(x, y)      = { x: ox + x*cell, y: oy + y*cell }
```

排查并统一了**全部**调用点：地板/墙/板/门/尖刺/星尘/水晶/锚/出口、出生提示、回响历史路径、玩家/守卫/回响实体、粒子特效。
`EchoRender.diagnostics(state?)` 返回当前帧每个实体的「实际绘制中心」与「逻辑格中心」的漂移；不传参则使用最近一帧 `lastState`。稳定帧（插值收敛后）`maxDrift ≤ 1` 即合格；移动插值进行中允许有偏差（另测轨迹）。

### 5.5 撤销

`main.js` 每次 `applyAction` 前把 `Engine.clone(state)` 压入 `G.undo`。**已移除第一轮的 400 步裁剪**，完整本局可撤销。快照包含 `timeline/history/player/echoes/guards/stars/crystals/anchor/status/deathCause/events`，因此撤销可逐字段恢复步数、位置、回响（含 `fromAnchor` 与起点）、守卫、星尘、水晶、门状态与胜负状态。
`G.settled` 在撤销胜利/死亡动作时复位，允许重新结算；`startLevel()` 清空撤销栈。

### 5.6 输入与帧循环

- `keydown` 立即处理一次并启动 110ms 定时连发；持续按住可连走，不依赖操作系统按键重复速率。
- `keyup` 清理 `heldSet`；`blur` / `visibilitychange` 清空按键并**自动暂停**。
- 逻辑瞬间推进，渲染侧每实体维护 `rx/ry`，按 `rx += (x-rx)*(1-exp(-dt/τ))` 缓动追赶，τ ≈ 45ms。
- `P` 切换暂停：暂停时 `act()`、`tickRepeat()`、`tickDemo()` 全部冻结。
- 事件队列由 `applyAction` 产出，`render.js` 消费为粒子、`audio.js` 消费为音效。

### 5.7 参考解自动演示（A1：与正式存档隔离）

```
startDemo():  startLevel(当前关) → mode='demo'; demoActive=true;
              demo = { queue: solution, i, at, undo: [] }（独立撤销栈）
tickDemo():   按 150ms 节拍 applyAction；禁止调用 onWin / onDead
              抵达出口或序列结束 → finishDemo(result)
finishDemo(): mode='demoDone' → 显示「演示完成」面板（重播 / 退出 / 关卡列表）
              不写 localStorage、不更新关卡解锁、不写最佳步数/星级
中断:         演示中任意非暂停键 → interruptDemo() → startLevel(当前关) 回正式初态
```

`onWin()/onDead()` 另有双重保险：若 `demoActive || mode==='demo'/'demoDone' || settled` 则直接返回。
`settled` 保证本局只结算一次，胜利后重复按键不改写纪录。

### 5.8 教程规则生成（A2）

`describeEchoRule()` 从 `LEVELS` 聚合出真实节拍描述（当前为「第 1 关每 6 拍；其余关卡每 4 拍」），标题教程与 HUD 倒计时都以此为准，**不再硬编码 `LEVELS[1].echoEvery`**。新增或修改关卡的 T 值会自动反映到教程。

## 6. 关卡编辑方式

修改地图只需编辑 `js/levels.js` 的 `map` 数组，无需改动代码。约束：

1. 所有行等长、四周必须是 `#` 墙；有且仅有一个 `S` 与一个 `E`；
2. 使用到的门字母必须有对应小写压力板（`!` 计入 a 通道），反之亦然；
3. 字符必须在 §4.1 字符表内，否则 `buildStatic` 抛错；
4. 改完后**必须**运行 `node tools/verify.js`：断言参考解胜利、`step ≤ par`、无多余动作、星尘/水晶全收集、确定性重播、撤销回放，以及含锚关卡的「去锚后不通关」。

`solution` 由 `U/D/L/R/W` 组成；可用 `node tools/probe.js <id> "<动作串>" --map` 逐步诊断，或用 `node tools/solver.js <id>` 自动求最短解（`keyOf` 已包含 `anchor`，保证锚点状态不被错误剪枝）。

## 9. 素材来源、许可与依赖

- **美术**：全部由 `render.js` 用 Canvas 2D 几何图元程序化绘制（圆角矩形、圆弧、多边形、粒子），无任何图片 / 图标字体 / 外部字体文件。
- **音效**：全部由 `audio.js` 用 Web Audio 振荡器与噪声缓冲实时合成，无音频文件。
- **字体**：仅使用系统字体栈（`PingFang SC` / `Microsoft YaHei` / `system-ui` 等），无内嵌字体。
- **第三方素材**：无。因此无第三方许可需要遵守。
- **运行依赖**：无 npm 包、无联网请求、无账号、无付费服务、无在线模型调用。
- **验收工具依赖**：`tools/browser_playtest.js` 需要本机 Chrome（`C:/Program Files/Google/Chrome/Application/chrome.exe`）与 Node ≥ 22 的内置 `WebSocket`/`fetch`；这两者都是环境自带，**不是游戏运行依赖**。若本机只有 Edge，把脚本顶部的 `CHROME` 常量改为 Edge 路径即可，无需安装任何包。
