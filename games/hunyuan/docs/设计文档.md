# 《回响 / ECHO》游戏设计文档（第三轮最终版）

> 一句话：**你无法同时出现在两个地方 —— 但过去的你可以。**
> 类型：网格制时间解谜 · 平台：浏览器（单页，双击即玩） · 关卡数：**12 关** · 预计时长：35–60 分钟
>
> 本文档描述**第二轮交付后的最终实际行为**。与第一轮的差异见 `ROUND2_CHANGELOG.md`。

---

## 1. 概念概述

《回响》是一个以「时间残像」为核心的回合制网格解谜游戏。

玩家在一张俯视网格地图中移动，目标是抵达出口。地图上有需要**持续被踩住**才会打开的压力板、巡逻的守卫、致命的尖刺、可收集的星尘与时间水晶。玩家本体只有一个人，而机关往往需要「同时」被多个人压制。

解决办法是：**把过去的自己留下来。**

每一拍（回合）都会记录玩家的动作。每当时间走过一定拍数，一个「回响」就会诞生 —— 它从几拍前你所站的位置出现，把你刚才走过的那段路重新走一遍，然后**定格在你触发它的那个位置上**，成为一尊不会消失（除非被顶替/撞碎/净化）的残像。

第二轮新增 **时间锚**：玩家可以记下一个位置，让之后诞生的回响**改从那里出发**去重走历史。于是残像不再只能落在「你现在站的地方」，而可以被投送到别处 —— 包括你自己踩上去会死、只有回响能站的地方。

### 设计目标

| 目标 | 说明 |
| --- | --- |
| 一屏看懂 | 规则可在 30 秒内讲清楚；标题界面给出真实的分关节拍规则；HUD 常驻倒计时与锚点状态 |
| 纯粹的推理乐趣 | 时间**只在玩家行动时**推进，没有手速压力，失败完全归因于规划而非操作 |
| 极低惩罚 | 完整本局无限撤销 + 一键重来 + 暂停，鼓励大胆试错 |
| 确定性 | 同一串输入必然产生同一结果，可回放、可求解、可逐拍截图核对 |
| 画面与逻辑同格 | 所有实体与地格共用唯一坐标变换，稳定帧中心误差 ≤1 CSS 像素 |

## 2. 核心循环

```
观察地图（门/板/锚/守卫布局） → 规划路线与节拍 → 输入一串动作
      ↓                                    ↑
   时间按拍推进，过去的位置不断被「定格」成残像  ←┘
      ↓
   残像压制住机关 → 道路打开 → 抵达出口 → 结算（星尘 / 步数 / 星级）
```

失败不是终点：踩到尖刺或被守卫抓到会弹出「时间回溯」面板，可退回上一步，也可重开本关。

## 3. 机制规则（逐条）

### 3.1 时间与拍

- 以「拍（beat）」为最小时间单位。**只有玩家行动时，时间才会推进一拍。**
- 每拍可执行 `上 / 下 / 左 / 右 / 停留` 五种动作之一。
- 试图走进墙或关闭的门时，动作仍消耗一拍，玩家原地不动。
- **节拍按关卡配置**：第 1 关 `T=6`，第 2–12 关 `T=4`。标题教程由关卡数据聚合生成，不再引用单一关卡的常量；HUD「拍后下个残像」始终显示当前关真实倒计时。
- 因此游戏完全确定：给定地图与输入序列，结果唯一，可回放、可推理、可求解。

### 3.2 回响（Echo）—— 核心机制

每隔 **T 拍**触发一次回响：

1. 回响在 **T 拍前**你所站的位置诞生（半透明发光轮廓）；
2. 在接下来的 T 拍里，逐步把你最近 T 拍的动作**重新执行一遍**；
3. 走完这段历史后**定格**在触发瞬间你所站的位置，静止不动；
4. 定格的回响持续压住压力板，直到消失。

> 玩家真正需要记住的一句话：无阻挡时，触发那一刻你站在哪，回响最终就定格在哪。
> **时间锚会改写这条**：起点从「T 拍前的位置」变成「锚点记录的位置」。

回响消失的四种方式：数量上限 M（FIFO 淘汰最老）、被守卫撞碎、时间水晶净化、撤销回溯。

其他规则：

- 回响**不是实体**：不阻挡玩家和其他回响，可被穿过；
- 回响会被墙和**关闭的门**挡住，若在重走历史时被挡住会卡住、无法到达预期位置；
- 回响不收集星尘、不触发尖刺，也不拾取时间水晶 —— 只有「现在」的你才有实体；
- 被时间锚改写起点的回响带 `fromAnchor` 标记，画面上绘有金色外环 + 菱形锚标，HUD 也可观察锚点记录。

### 3.3 压力板与门

- 压力板 `a b c d`，同字母的门 `A B C D`。**同一通道的全部压力板都被压住，对应门才开启。**
- 「被压住」的判定：该格上有玩家**或**任意回响（含正在追赶中的回响）。
- 门在某拍**开始瞬间**求值并冻结整拍，保证行为可预测。
- 新增 **尖刺压力板 `!`**（通道 a）：该格同时是尖刺与压力板。玩家踏入即死，但回响无视尖刺、可以站上去压板。
  这构成了第二轮新关卡的核心约束：**普通回响只能定格在玩家触发时所站的位置，玩家又永远站不上尖刺板，因此只有被时间锚改写起点的回响能压住它。**

### 3.4 守卫

- 守卫沿直线巡逻，每拍移动一格；前方是墙、关闭的门或另一守卫时原地**掉头**。
- 守卫进入玩家所在格 → 玩家被抓，失败。
- 守卫即将踏入有残像的格子 → 该格全部残像碎裂，守卫被迷惑、**原地停顿一拍并掉头**。残像是一次性肉盾。
- 守卫永远沿初始方向所在直线往返，位置完全可预测，不存在随机与手速要求。
- 守卫由第 4、7、15 关承载：第 4 关教学、第 7 关组合、**第 15 关门后走廊守卫把关「哪一拍能过咽喉」**（11-07 按玩家反馈加回）。它不改变门的几何割集，只把「门开了就能过」收紧成「门开了还得挑对拍」，也让望远镜的守卫预警在终章真正派上用场。

### 3.5 尖刺与时间水晶

- 尖刺 `x`：玩家踏入即失败（回响无视尖刺）。
- 时间水晶 `o`：**集齐本关全部水晶，出口才解锁**（未解锁时出口显示暗色带「锁」字）。拾取水晶会**立刻净化场上全部回响**。
- 两者叠加产生「顺序」维度：先取水晶再布置残像，否则辛苦布好的残像会因一次拾取全部蒸发（第 6、10、12 关）。
- 锚点记录**不随水晶清除或复制**，也不暂停时间。

### 3.6 时间锚（第二轮新增机关，完整规则）

地图字符 `^`。

1. **记录**：玩家踩上锚点（含原地等待）时，以「当前位置 + 当前拍数」记录 `anchor = {x, y, step}`；再次踩锚**覆盖**上一次记录。本关重开时清空。
2. **生效时机**：仅在「达到 T 节拍、且本拍确实新建了回响」时触发；没有新回响的拍不触发。
3. **作用对象**：只作用于**本拍新建、创建序号最小**的那只回响（实现上每拍只新建一只，即该只）。把它的**起始位置**固定为记录点；动作序列 `seq` 不变，仍是最近 T 拍的动作，因此它的最终定格位置随之平移。带 `fromAnchor` 标记。
4. **合法性**：记录点必须是合法可通行地格，**不能被墙或关闭的门占用**。判定使用拍初冻结的门状态，保证确定性。
5. **阻挡**：若锚点格已被玩家、守卫或**其它回响**占据，本次触发**不移动也不替换格上实体**，该回响**保留原起点**，绝不随机改选另一只。事件 `anchorIgnored` 可被观察。
6. **不复制状态**：锚点不暂停时间，不复制星尘/水晶状态。
7. **撤销**：`anchor` 与回响起点都在状态快照里，撤销逐字段完整回滚。
8. **可观察**：锚点格绘菱形，已记录时高亮并显示记录拍数；HUD 第五格显示「时间锚：第 N 拍 @x,y / 未记录 / —」；锚生回响带金色外环与菱形标记。

### 3.7 星尘与评价

- 星尘 `*`：可选收集品，玩家走过即拾取（回响不能拾取）。
- 每关最多三星：**① 抵达出口 ② 集齐本关全部星尘 ③ 总拍数 ≤ par**。
- 本轮 12 条内置参考解**全部集齐星尘与水晶**，即三星可达（由 `tools/verify.js` 断言）。
- 进度保存在浏览器 `localStorage`。**参考解演示不写入任何正式纪录**（见 3.8）。

### 3.8 演示、暂停与存档隔离

- **参考解演示（`H` / 顶栏按钮）**：自动逐拍回放内置解，到达出口后显示「演示完成」面板，可重播 / 退出 / 去关卡列表。它使用**独立的演示撤销栈**，不调用正式结算，**不写星级、最佳步数、解锁或胜利统计**。演示中按任意非暂停键即中断并回到本关起点。
- **手动通关**：正常按规则写入 `localStorage`。
- **暂停（`P` / 顶栏按钮）**：暂停时输入被忽略、演示节拍冻结；窗口失焦或切到后台会**自动暂停并清空按键状态**，切回后需按 `P` 或点「继续」恢复。
- **结算幂等**：本局只结算一次；胜利后继续按键不重复写纪录。
- **撤销**：完整本局可撤销（不再有 400 步裁剪），可撤销胜利/死亡动作；重来清空撤销栈。

### 3.9 时间望远镜（第三轮核心升级，完整规则）

按键 `V`（触屏点「预演」钮）。**语义 = 等待一拍 + 显示预测**，不是免费的查看。

1. **代价**：按 V 推进一拍（与空格完全等价），会改变残像诞生节奏与守卫相位。用一拍的时间换确切的未来，是真实取舍。
2. **显示内容（引擎保证确定，绝不编造）**：
   - **青色双环准星**：每只在场（未定格）残像重演完毕后将**定格的格子**；
   - **红色 ✕**：该残像途中会被守卫撞碎（资源损失预警）；
   - **灰色 ✕**：该残像会因数量超限被挤出（未定格就消失）；
   - **紫色虚线菱形（标「下」）**：下一只残像的**出生点**；若出生点被时间锚改写则显示金色外环，被占用/阻挡无法改写时显示原因；
   - **玩家周围红色脉冲**：若原地不动，会在第 N 拍因守卫/尖刺死亡。
3. **不可预测的不输出**：下一只残像的**冻结位置**取决于玩家接下来的走法，望远镜不显示。
4. **实现**：`Engine.predict(state)` 在状态 clone 上逐拍模拟等待（守卫按拍数巡逻、残像按已录序列重演，均与玩家未来走法无关，故可精确预测），不触碰真实状态；任何新动作或撤销都会使预测过期（`G.prediction = null`）。
5. **过期语义**：预测是「此刻的快照」，走一步、等一拍、撤销都会清除叠加层，需重新按 V。
6. **与参考解的关系**：V 在引擎中等价于 `W`，因此**参考解不依赖 V 也能通关**——望远镜是信息工具，改变的是决策方式（从心算节拍变成可见规划 + 节拍代价的权衡），不是新的物理。`tools/regress.js` R8 逐格断言预测与实际一致。

## 4. 关卡设计

设计原则：**每关只引入一个新概念**，前一关的知识是后一关的工具；并且**门必须是起点到出口的几何割集**——关掉全部门就到不了出口，压力板与门至少隔 2 格（玩家自踩板最多撑过一拍）。这条约束是 11-06 针对玩家反馈「直接走过去就行」补上的，见下文「机关必要性」。第 1、3–7 关原样保留；第 2、8–15 关在 11-06 重设计了地图与参考解（机制不变）；11-07 按玩家反馈把第 15 关的门后守卫加回，地图与参考解随之更新。

### 机关必要性（11-06 新增的硬性关卡约束）

关卡只验证「参考解能通关」是不够的：若门是地图里孤立的一格，玩家可以从旁边绕到出口，整关的残影 / 锚 / 望远镜在解题上就是可选的。`tools/audit.js` 对每关给出两条独立证据，并已并入 `verify.js` 作为永久断言：

- **[G] 几何割集**：全部门视为永久关闭、尖刺视为不可通行，BFS 从 S 到 E 必须**不可达**。
- **[N] 无机关可解性**：真实引擎中禁用全部回响（`echoEvery` 极大、`maxEchoes=0`），完整 BFS 搜索（含守卫、尖刺、水晶、玩家自踩板）必须**无法通关**。

修复前 10/15 关违反这两条（含第一轮遗留的第 2 关），证据在 `tools/audit-before.log`；修复后 15/15 通过。`tools/regress.js` R10 把 9 条修复前的绕行路径固化成永久回归断言。

**除「机关必要」外，终章还要求「时序必要」**（11-07 新增）：第 15 关的门后走廊有一名守卫，`tools/guard_evidence.js` 用「把守卫拿掉」的反事实变体给出三条证据 —— ① 两版最短全收集解同为 26 步但**动作串完全不同**；② 在踏入咽喉前多等一拍，有守卫版第 26 拍被抓、无守卫版仍能通关；③ 对参考解做 53 条单点扰动（插入/删去一拍），有守卫仅 1 条仍可通关、无守卫有 7 条。R10g/h/i 把这三条固化为回归断言。注意这是「单点扰动口径下的时序收窄」，不是对全部动作串的严格数学唯一性证明。守卫放在门后而非门旁，因此不会像旧版那样在几何上形成绕过 A 门的替代通路。

每关内置一条参考解，可由「参考解」演示观看；这些解由 `tools/verify.js` 逐拍回放校验（胜利、par、星尘、水晶、确定性重播、撤销回放、机关必要性）。地图改动先经 `tools/redesign.js` 验证「割集 / 必要性 / A\* 可解」再写回；参考解与 par 由 `tools/solver.js` 机器求解回填。关卡采用字符地图，修改地图不需要改代码。

## 5. 操作与界面

| 输入 | 动作 |
| --- | --- |
| `↑ ↓ ← →` / `W A S D` | 移动一拍 |
| `空格` / `.` | 停留一拍（凑触发时机） |
| `V` | **时间望远镜**：预演一拍（= 等待一拍 + 显示确定性预测叠加层） |
| `Z` / `Backspace` | 撤销上一拍（完整本局无限） |
| `R` | 重来本关 |
| `P` | 暂停 / 继续（失焦会自动暂停） |
| `Esc` | 关卡列表 |
| `H` | 参考解自动演示（不写入纪录） |

移动端提供屏幕虚拟方向键 + 等待 / 预演 / 撤销 / 重来按钮。

界面：
