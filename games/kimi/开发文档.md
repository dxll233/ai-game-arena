# 《星港守夜人》开发文档

## 1. 技术方案

- **运行形式**：静态网页，直接打开 `index.html` 即可运行。
- **技术栈**：HTML5、CSS3、原生 JavaScript、Canvas 2D、Web Audio API。
- **依赖**：无第三方库、无网络请求、无构建步骤。
- **逻辑分辨率**：1280 × 720；Canvas 按窗口等比缩放，输入坐标映射回逻辑坐标。


## 3. 架构设计

### 3.1 状态机

`menu → playing ↔ paused / levelup → gameover | victory → playing`

- `menu`：展示标题、操作和最高分。
- `playing`：更新输入、实体、碰撞、波次、粒子与计时。
- `paused`：冻结逻辑，仅保留渲染。
- `levelup`：冻结战斗并显示三项升级。
- `gameover / victory`：展示结算，可重置所有运行时数据。

### 3.2 核心对象

- `Game`：唯一主控，管理状态、数组、计时、波次、分数与渲染。
- `player`：位置、速度、生命、武器、经验、升级属性和冷却。
- `enemies[]`：普通敌人与首领共用圆形碰撞模型，通过 `type` 区分行为；盾卫有转向速率，布雷者部署地雷。
- `bullets[]`：玩家和敌方弹丸，通过 `friendly` 区分阵营，通过 `weapon` 区分脉冲、霰弹和蓄能表现。
- `hazards[]`：可拆除地雷和Boss熔断区，具有预告、触发、伤害与回收生命周期。
- `obstacles[] / arenaHazard`：熔炉场地的实体掩体与周期热泄带；开放泊位仍为空旷场地。
- `gems[]`：经验掉落物，具备磁吸与拾取逻辑；没有治疗拾取物。
- `combatLog[]`：最多400条伤害/治疗记录，供结算核查；不提供玩家调试按钮。
- `particles[] / texts[]`：纯视觉反馈，不参与游戏判定。

### 3.3 主循环

使用 `requestAnimationFrame`。逻辑步长限制在 0.033 秒内，避免切换标签页后出现超大位移。`loop()` 用 `try/finally` 注册下一帧，任何单帧异常都不会中断渲染链，异常次数记入 `frameErrors`。每帧顺序：

1. 计算 `dt` 并处理暂停状态。
2. `updatePlayer()`：持续回复、移动/蓄力减速、瞄准、射击和冲刺。
3. `updateSpawner()`、`updateEnemies()`：生成与AI，接触伤害在此发生。
4. `updateArena()`、`updateHazards()`：热泄带、地雷与熔断区。
5. `updateBullets()`、`updateGems()`、`updateEffects()`：弹丸碰撞、经验与视觉反馈。
6. `updateWave()`：波次完成后修复12点；最后 `updateHUD()` 读取最终HP。

因此同帧约定为“持续回复 → 接触/场地/弹丸伤害 → 波间修复 → HUD”。升级即时治疗在 `levelup` 状态选卡时执行；致死伤害先进入失败结算后，不再接受波间或升级治疗。`healPlayer()` 统一钳制0至最大生命并记录来源，`hurtPlayer()` 统一处理0.72秒受击无敌与日志。

## 4. 关键实现约定

- 所有实体使用 `{x, y, r}` 圆形碰撞；距离比较优先使用平方距离。
- 弹丸设置生命周期和越界回收，避免数组无限增长。
- 删除实体采用倒序遍历或标记后过滤。
- 玩家受击由 `invuln` 控制；冲刺期间不受伤。
- 升级候选从强化定义池随机抽取，同一轮不重复。
- 多发弹丸围绕瞄准方向等角展开；暴击在单发子弹生成时判定。
- 首领阶段依据当前生命比例切换，阶段转换只触发一次。
- 页面失焦时自动暂停，防止玩家离开窗口后被击败。
- 本地最高分使用 `localStorage`，读写均捕获异常；没有局中存档或账号。
- 武器由 `player.weapon` 分派。脉冲/霰弹按住连续射击；蓄能枪桌面松开发射，触屏满蓄自动发射。切换会清空未发射蓄力。
- 瞄准辅助默认关闭；开启后按敌人ID保持目标，死亡后才重选，不会每帧抢换目标。
- 盾卫正面弹丸伤害为30%，盾转向速率2.2弧度/秒；布雷者的地雷可被弹丸拆除。
- Boss锁定齐射和熔断区交替使用，二阶段增加数量并缩短间隔；预告实体只触发一次并回收。
- `start()` 清空按键、摇杆、蓄力、弹丸、危险区和分数；`runId` 隔离上一局升级链的延迟回调。没有发布版跳关、加血或时间加速入口。
- `obstacles` 与 `arenaHazard` 在构造期由 `setupArena()` 初始化，并在 `selectArena()` 切换场地时重建。菜单状态同样会调用 `drawArena()`，不能假设二者只存在于 `playing` 状态。

## 5. 触屏适配

- 通过 `pointer` 事件统一鼠标与触摸输入。
- 左侧摇杆输出归一化二维向量，松开立即归零。
- 触屏游玩时自动选取最近敌人作为目标并连续射击。
- 冲刺与武器循环按钮独立于摇杆，避免多指操作冲突；武器卡不遮挡摇杆。
- 使用 `touch-action: none` 阻止游戏区域滚动和缩放干扰；390×844使用紧凑菜单、升级卡和结算布局。

## 6. 音效实现

首次用户交互后创建 `AudioContext`。使用振荡器、增益包络合成短音效；提供静音按钮。音频初始化失败不影响游戏逻辑。

## 7. 测试计划

- **静态检查**：JavaScript 语法检查；确认 HTML 引用文件存在。
- **启动流程**：开始按钮进入战斗，HUD 和玩家正确初始化。
- **核心操作**：移动、瞄准、射击、冲刺、暂停均有效。
- **战斗逻辑**：子弹能伤害并消灭敌人，敌人能伤害玩家，经验可拾取。
- **成长逻辑**：升级弹层出现，选择后属性生效并恢复战斗。
- **流程逻辑**：波次可推进，首领可生成，胜负结算和重开有效。
- **适配检查**：窗口缩放后画面比例与鼠标坐标保持正确。
- **交付检查**：断网条件下无外部资源依赖。

## 8. 第二轮验证

测试仅使用 Node.js 22 内置模块和本机 Chrome/Edge，不需要 `npm install`。在本目录运行：

```bash
node --check game.js
node tests/hp-matrix.test.cjs
node tests/mechanics.test.cjs
node tests/state-flow.test.cjs
node tests/arena-selection.test.cjs
node tests/browser-smoke.cjs
node tests/browser-playthrough.cjs
```

- 回血矩阵：3种治疗来源 × 5种初始HP × 5种时序（含无敌）× 10次，断言HP上下限、日志顺序与HUD；另有30次独立无敌伤害与同帧52点复现。
- 机制测试：三武器各10次攻击，记录发射、命中、耗时；覆盖蓄力阈值、移速代价、散布、回收、升级相关属性、稳定辅助、触屏满蓄；两种新敌人各20次行为更新；Boss两种新攻击在两个阶段各5次。
- 状态测试：五波配额、Boss、暂停、失败、胜利、重复结算、连续重开10次、升级回调跨局隔离。
- 浏览器测试：断网 `file://` 启动、真实键鼠输入、自然失败、真实UI重开10次、1280×720/893×764及390×844模拟触控。CDP脚本不修改游戏状态；完整战斗结果和人工未覆盖项以 `TEST_REPORT_ROUND2.md` 为准。
- 场地选择回归：按玩家时序「点 02 / 熔炉环线 → 等待真实帧 → 点开始守夜」验证主循环存活、`frameErrors` 为 0、敌人生成与 HUD 可见，并覆盖切回 01 场地。此用例专门防止菜单切场地时渲染异常打断 `requestAnimationFrame` 链。
- headless Chrome 的 `Target.activateTarget` 不产生真实窗口失焦，失焦自动暂停改由派发 `window.blur` 验证；该项不属于真实标签切换的验证结果。

首版自述不再作为第二轮证据；第二轮没有新增外部素材或运行时依赖。
