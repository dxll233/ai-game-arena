## 0. 热修记录（v3.0.1，收到"游戏无法开始"反馈后）

### 0.1 主菜单"开始游戏"按钮在中小视口被挤出屏幕（已修复）

- **现象**：用户反馈"游戏无法开始"。根因是主菜单弹层布局三重问题叠加：
  1. `.ov-card` 作为 flex 列布局子项默认 `flex-shrink:1`，被父容器高度压缩（内容 909px 被压到 568px，按钮随滚动区藏到首屏外）；
  2. 三张地图卡总宽 544px 超过菜单卡内容宽 440px，被迫竖排成 459px 高，把按钮推到距卡片顶 769px 处；
  3. 中小屏下弹层 `position:absolute` 受画布区高度限制（如 1024×700 时弹层仅 460px 高）。
- **影响视口**：1024×700、768×600、390×844、360×640 等高度 ≤700px 或宽度 ≤900px 的窗口下按钮不可见（1280×800、893×764 恰好放下故未暴露）。
- **修复**：`flex-shrink:0` 防止压缩；菜单卡加宽至 640px 使三图卡横排；≤1100px 视口弹层改 `position:fixed` 覆盖整个视口；窄屏地图卡改 2 列网格并隐藏操作速查表与氛围介绍段；修复 media query 层叠顺序问题（原写在基础规则之前被覆盖）。
- **验证**：6 种视口（1280×800 / 1024×700 / 893×764 / 768×600 / 390×844 / 360×640）按钮全部首屏可见可点、点击后正常进入游戏、无横向溢出（截图 40-43）；Node 仿真 169 项无回归；浏览器试玩 27 项无回归；暂停/失败/胜利/图鉴/时间线弹层在 3 种视口下按钮均可达。

## 1. 剩余问题

### 1.1 局内存档续玩不支持（设计决策，非缺陷）

- **影响**：单局约 12-18 分钟，刷新页面或返回主菜单会结束本局，不能从中波次继续。
- **理由**：序列化中局状态（波次生成队列、技能 CD、特效实体）复杂且易产生坏档；本作定位"一局一把"塔防，冒险价值大于收益。纪录与解锁不受影响。
- **临时处理**：尽量在波次间隙暂停后再离开；失败/胜利纪录自动保存。

### 1.2 手机触控未官方适配（布局已适配，触控未测）

- **影响**：v3.0.1 起布局在 390×844 / 360×640 窄屏已完整可用（开始按钮、地图卡、弹层按钮均首屏可达，无横向溢出）；但触屏操作精度（点选建塔格、小按钮）未经真机测试。
- **状态**：未做真机触控测试。桌面键鼠为唯一官方支持平台。
- **临时处理**：桌面浏览器游玩；如用平板/手机横屏可运行但体验不作保证。

### 1.3 音效为程序化合成，无背景音乐

- **影响**：复古街机合成音效（方波/噪声），部分玩家可能觉得单薄；全程无 BGM。
- **理由**：单文件零外部素材约束下的自主选择，音效分层（射击/爆炸/冰冻/技能）清晰可辨。
- **临时处理**：可用顶栏滑块调低音量或静音。

### 1.4 2x 倍速下音效抽稀可能仍显密集

- **影响**：同音效最小间隔已在倍速时翻倍抽稀，但极端高压场景（18 塔齐射）下合成音叠加仍可能偏吵。
- **复现**：第 19-20 波开 2x 倍速，听射击/爆炸音。
- **临时处理**：调低音量或切 1x。

### 1.5 仿真机器人与真人操作的差距

- **影响**：Node 仿真机器人以"分支优先→升级→扩建"固定策略三图通关（各剩 15-20 生命），证明游戏可通关且有挑战余量；但真人玩家的操作习惯（乱序建塔、憋钱、不进阶）可能导致失败。
- **说明**：这是塔防难度曲线的正常组成部分（教学波容错高、后期考验情报与分支决策），非平衡缺陷。
